# 杏林大健康 AI 问答系统

**2026.XX - 2026.XX**（起止时间请按实际填写）

## 项目背景

医疗健康咨询对准确性与可追溯性要求极高，大模型一旦编造医学结论会直接影响用户健康决策。但通用大模型直接使用有三个短板：结构化知识取不到、回答无来源不可追溯、无依据时仍强行作答。为此独立开发一套可溯源、可降级的问答服务——以知识图谱承载确定性知识、以文献检索承载开放性知识，由 Agent 自主调度工具，并用事实护栏守住"无依据不硬答"的底线；统一承载 8808 条疾病知识与 19 篇医学文献



项目痛点（解决的甲方问题）：我们的项目甲方属于大健康行业，之前他们内部新人培训周期在一个多个月，周期很长，因此他们希望能够开发出一套供内部人员使用的大健康知识问答系统，在这个系统的帮助下新人可以很快的熟悉行业知识和上手系统，在作为咨询人员回答用户的信息时可以根据问答系统的答案进行简单编辑就可以回答用户的问题，既可以减少人员培训周期又可以保证对客户回答的专业性

项目背景（我们开发了什么）：应甲方要求开发一套可以用于大健康行业知识的智能问答系统

## 技术栈

Python / FastAPI / LangChain + LangGraph / Neo4j（知识图谱）/ Milvus（向量库）/ Redis /
DeepSeek / Clean Architecture / RRF 融合 / NL2Cypher

## 工作职责

**1、系统架构设计**：独立完成分层架构设计（接口 / 应用 / 领域 / 基础设施四层），把领域逻辑与
数据库、大模型等外部依赖彻底解耦，核心组件进程内单例复用；并引入**自动化架构检查**，出现跨层
直连会立即失败，让"分层"从约定变成可执行的约束。

**2、知识层构建与问答引擎**：将 8808 条疾病语料构建为 **7 类节点、10 类关系**的知识图谱
（含 16783 条「疾病—科室」关系），19 篇医学文献处理为 762 条切片接入向量库；设计**元数据驱动的
查询引擎**，**20 类固定问答由配置自动生成查询语句、零大模型调用**，新增类型无需改动查询层。

**3、多工具编排 Agent（ReAct）**：基于 LangGraph 实现 ReAct 循环，由模型自主选择工具而非写死路由。挂载两类工具：图数据库查询（自然语言 → 查询语句 → 安全校验 → 执行 → 结构化事实）与混合检索（稠密向量 + 稀疏关键词双路召回融合），分别覆盖确定性与文献类问题。亮点：工具失败降级为可读的观察结果，模型据此自主换工具或如实承认查不到；循环异常时回落基础流水线兜底；结果统一标注来源并经事实护栏二次核查。实测要点覆盖率 97.4%、端到端 P50 5.9s。

**4、接口开发与分级容错**：交付命令行与 Web 双入口。并实现分级降级链路——图谱、向量库、大模型、缓存任一失效时服务仍能作答，并如实反映能力下降；非法请求在入口即被拒绝，不做任何检索与大模型调用。安全侧实现全链路参数化 + 只读隔离，与入口拦截、执行前校验共同构成四道防线。实测四类依赖逐一失效均不中断，20 并发零错误、端到端 P50 5.9s。	

**5、工程质量与可验证性**：按分层架构 + 端口-适配器组织代码，把领域逻辑与外部依赖彻底解耦，并用自动化架构检查固化依赖方向；沉淀 199 个完全不依赖外部服务的离线测试用例（数据库与模型全部以替身注入），可直接接入 CI，核心链路覆盖率 95%。开发期据此定位并修复 11 个真实缺陷，含"大模型 Key 失效时异常直接抛给用户"与"大结果集查询未截断"两处。
