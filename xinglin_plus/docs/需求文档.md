## 一之补、固定问答类型（第 9 章）

需求原文是"**至少**支持以下 18 类"——所以这 18 类**只能加、不能改**：

| 编号 | 类型 | 实现 |
|---|---|---|
| 1~18 | 第 9 章原文的 18 类 | `domain/values.py::QAType`；编号与名称由 `tests/test_graph_schema.py` **逐字**固化为断言 |
| 19 | 疾病—科室 | `QAType.DISEASE_DEPARTMENT` → `(Disease)-[:belongs_to]->(Department)` |
| 20 | 科室—疾病 | `QAType.DEPARTMENT_DISEASE` → 反向 `belongs_to` |

19/20 来自**需求 14.7「科室数据（科室名称 + 相关疾病）」**，原 18 类未覆盖。
图谱实测：`belongs_to` 16783 条、覆盖 **8807/8808** 疾病，54 个科室 —— 数据齐备，
因此接成零 LLM 的模板快路径（而非只靠 NL2Cypher 兜）。

## 五、已知缺口（如实记录，不粉饰）

| 项 | 需求 | 现状 | 说明 |
|---|---|---|---|
| **药品厂商识别** | FR-002 要求识别「药品厂商」 | **未接入** | 既有图谱数据不可用：`Producer` 节点名是「厂商 + 药名」的拼接串（如「999华蟾素口服液」，共 17201 条），`drugs_of` 仅 **251** 条且指向**同名节点**（药名 == 厂商名）。这类脏名字**更长**，在「最长优先匹配」里会压过正确实体（实测「太极阿胶能吃吗」被识别成 Producer，而非食品「阿胶」）——因此词典**不加载** `producer.txt`。根因是 `build_graph.parse_drug_detail` 括号内外配对颠倒，数据修好后即可启用 |
| **过期 / 冲突内容处置** | 14.8：过期内容应能标识或下线；多来源冲突按权威度、时间取优 | **未实现** | 属知识库**运维机制**，当前由人工流程承接（建库脚本 `MERGE` 幂等、可重复执行） |
| **依据检查失败的用户侧告知** | 12.5：不得因此声称已做过可靠性确认 | **部分** | 护栏 fail-open 时内部已记 `reason="核查失败，跳过"`，但用户可见层没有标注"本次未核查" |

## 六、验收要点

| 项 | 判据 |
|---|---|
| 四形态可用 | `--mode hybrid / rag / nl2cypher / agent` 均能端到端作答 |
| 自动选路 | 固定问答走 KG、开放式走文献或多路，`direct` 不检索 |
| 降级不中断 | 图谱不可用回落规则链；文献不可用退化为仅 KG/仅 direct；LLM 不可用回落规则流水线 |
| 护栏生效 | 有据时原样返回；无据时追加提醒；核查失败时不阻塞 |
| 溯源可查 | 文献片段带「来源文件 + 页码」 |
| 可测试性 | `pytest tests/ -q` 全绿，且**不依赖外部服务** |
