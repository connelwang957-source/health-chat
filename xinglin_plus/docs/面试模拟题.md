# 面试模拟题（杏林大健康 AI 问答系统）

> 依据简历的「项目背景 / 技术栈 / 工作职责」出题，**业务 10 道 + 技术 10 道**。
> 每题统一三段：**题目 → 考察点 → 答题要点**（要点可直接用于自测，也可以顺着往下深挖）。
> 文末附「追问链」——面试官最常用的连续深挖路径。

---

# 一、业务方向（10 题）

### B1. 你说医疗问答要"宁可少答，不可答错"，这句话在你的系统里具体落在哪儿？

**考察点**：是不是真有风险意识，还是只会喊口号。

**答题要点**：
- **不答**：信息不足时走 10.3 标准话术（"依据不足"），不硬编；
- **降级答**：`Reliability` 分级（high / partial / low），low 时提示"仅供参考";
- **答完再查**：事实护栏做第二次 LLM 核查，无依据就在末尾追加"请谨慎参考"；
- **边界**：涉及诊疗给风险提示（10.4）+ 免责声明，不诊断、不开方；
- **一句话**：不是"不回答"，而是"**不把它当确定结论来回答**"。

---

### B2. 为什么要专门做 18 类固定问答？全部交给大模型自由回答不行吗？

**考察点**：能不能说清"确定性路径"的价值，而不是"技术堆砌"。

**答题要点**：
- 这 18 类是**可枚举的信息需求**（症状、忌口、并发症、用药、检查…），图谱里是**确定的结构化关系**；
- 走模板链：**零 LLM 成本、结果确定、毫秒级**，而且**不会编**；
- 全交给大模型：慢、贵、结果不稳定（同一问题两次答案不同），还得靠护栏兜底；
- 分工是"**简单问题走快路径，开放问题才动用 LLM**"（这也是 FR-024 的原话精神）。

---

### B3. 用户问"螃蟹不能吃吗"，系统怎么保证"不能吃"这个方向判断是对的？

**考察点**：知不知道"宜忌"是**方向敏感**的，而不是简单关系查询。

**答题要点**：
- 图谱里疾病-食品有**两条反向关系**：`no_eat`（忌吃）和 `do_eat`（宜吃）；
- 用户措辞"不能 / 不宜 / 忌 / 避免"→ 判 **restrict** 方向，否则是 recommend（`rules/diet_rule.py`）；
- 还要看**实体角色**：问"螃蟹"时主实体是 **Food**、疾病是目标 → 走 `FOOD_DISEASE_AVOID`（第 13 类）；
- 如果问"感冒不能吃什么"，主实体是 **Disease** → 走 `DISEASE_FOOD_AVOID`（第 11 类）；
- **坑**：同一个问句换个实体角色，查的边是反的 —— 这是 10.1 规则存在的原因。

---

### B4. "浑身没劲、流鼻涕怎么回事"——图谱里当然查不到，系统该怎么答？

**考察点**：是否理解**两路召回为什么要并存**。

**答题要点**：
- 这是"**症状描述**"而非"实体-关系"提问，图谱的精确匹配天然失效；
- 但向量检索能靠**语义**把这类口语表达关联到"感冒"相关文献/症状；
- 更完整的做法是 `SYMPTOM_DISEASE`（症状→疾病反向查）+ 文献语义检索**双路**；
- 这正是混合检索的价值：**语义相似**和**关系精确**覆盖的是两类不同信息需求。

---

### B5. 为什么健康问答一定要保留出处？没有出处会怎样？

**考察点**：产品责任感 + 对"可追溯"的理解。

**答题要点**：
- **可验证**：用户/医生能回原文核对，而不是"系统说的一定对"；
- **可审计**：出了问题能追溯到依据来源；
- **责任边界**：说清"信息来自哪里"，把"参考"和"诊疗"分开；
- 没有出处的后果：用户**无法判断可信度**，一旦有错也无从追责；
- 本项目做到：摘要级（每个文献片段带"来源文件 + 页码"）+ 展示级（前端可折叠来源列表）。

---

### B6. 系统怎么处理"我真的不知道"这种情况？

**考察点**：会不会**硬答**，以及"不知道"的工程实现。

**答题要点**：
- 召回为空（`is_insufficient`）→ 走标准"信息不足"话术，不编造；
- 召回有但**答案没依据** → 护栏追加提醒，同时把可靠性降到 low；
- 已经检索到证据但**模型答不上** → 如实说明"资料未包含这一部分"（本项目实测出现过：问高血压非药物治疗，检索到的文献都是别的主题，模型答"无法系统回答"并列出资料实际覆盖的内容）；
- 关键：**把"不知道"设计成一种正常回答形态，而不是失败**。

---

### B7. 哪些问题系统应该拒绝回答？怎么识别？

**考察点**：安全边界的落地手段。

**答题要点**：
三类：
1. **非法/越权查询**：写库、注入、越权读取 → 规则拦截（12.7 `query_guard` + Cypher 校验），返回"该请求已被拒绝执行"；
2. **超出能力边界**：确诊、开方、替代就医 → **不硬拒**，而是"回答 + 风险提示 + 建议就医"（医疗场景"提醒不拦截"）；
3. **与健康无关**：走 `direct` 不检索，简短回应或引导回健康话题。

**为什么 2 用提醒而不用拒绝**：可用性 + 责任边界（拒答会让大量正常问题一起失效）。

---

### B8. 老年用户问"我血压高，该吃什么药"，系统怎么答才算合适？

**考察点**：是否理解**医疗合规**与**产品体验的平衡**。

**答题要点**：
- **不能**给出具体药名+剂量当作处方（不给诊疗结论）；
- **可以**给：该疾病在知识库中的用药方向（图谱里确有"疾病→药品"关系）、用药注意事项、**必须遵医嘱**的强提示；
- 必须触发**风险提示**（10.4）与免责声明；
- 语气上：不制造恐慌、不承诺疗效，引导**就医**而不是自行用药。

---

### B9. 你怎么衡量这个问答系统"好不好"？列出你会用的指标。

**考察点**：有没有**评测意识**，而不是只有"能跑"。

**答题要点**：
| 维度 | 指标 |
|---|---|
| 检索质量 | Recall@k、命中率、无关片段占比 |
| 生成质量 | **幻觉率**（无依据陈述占比，对应 ACC-020/021）、依据不足率、答案完整度 |
| 可追溯 | 来源标注覆盖率、出处正确率 |
| 效率 | 首字时延 / 总时延、LLM 调用次数/成本、缓存命中率 |
| 稳定性 | 降级触发率、异常率、各依赖可用性 |
| 体验 | 用户追问率、点开来源的比例、满意度 |

**加分**：能说出"**幻觉率要人工抽样标注**，因为自动指标只能做辅助"。

---

### B10. 如果业务方要求"提高回答率、少说依据不足"，你怎么办？

**考察点**：**权衡与原则**，会不会为了指标牺牲正确性。

**答题要点**：
- **先明确红线**：不能靠"让模型自由发挥"来提升回答率——那是在制造幻觉；
- 正当手段：
  1. **扩语料**（更多文献/指南），覆盖率上去了，"依据不足"自然减少；
  2. **提升召回**（rerank、查询改写、多路融合权重调优）；
  3. **区分场景**给"通用健康常识"（明确标注"非知识库依据"）而不是混进证据里；
  4. 提示语优化（把"依据不足"换成更有帮助的引导，但不改事实）；
- **底线**：宁可回答率低，不可让用户把编造内容当医学事实。

# 二、技术方向（10 题）

### T1. 稠密检索为什么用 IP（内积）而不是余弦或 L2？归一化和度量必须配套吗？

**考察点**：metric 与 embedding 处理的关系。

**答题要点**：
- **L2** 是几何距离（受向量模长影响）；**IP** 同时受方向和长度影响；**余弦**只看夹角；
- embedding 做了 `normalize_embeddings=True` 后 `|a|=|b|=1`，于是 `a·b = cos(a,b)` → **用更便宜的 IP 拿到余弦语义**；
- **必须配套**：只归一化不改 IP（多余开销）或只改 IP 不归一化（语义被模长污染）都不对；
- 本项目：`DENSE_INDEX = {"metric_type": "IP"}` + `normalize_embeddings=True`。

---

### T2. FLAT 和 HNSW 怎么选？你的集合多大，选了什么，为什么？

**考察点**：会不会**按数据量做选型**。

**答题要点**：
- FLAT：与全量算距离 → **100% 召回**，O(N)，慢；
- HNSW：分层图近似检索 → 快（近对数级），**可能漏召回**，内存开销更大；
- 本项目集合仅 **762 条** → FLAT 精确且零调参；
- 转折点：到**百万级**、延迟成瓶颈时再换 HNSW，用少量召回率换速度；
- 加分：能提"如果要换，应该**用评测集对比换前换后的 Recall**，而不是拍脑袋换"。

---

### T3. RRF 为什么按"排名"融合而不是按"分数"融合？融合分能用绝对阈值卡吗？

**考察点**：这是最容易被追问的一道，也是项目真踩过的坑。

**答题要点**：
- 两路分数**量纲不同**（余弦 ∈ [-1,1]；BM25 分无上界）→ 不能直接加权相加；
- RRF 用 `Σ weight/(rank + c)`（c=60）→ **天然规避量纲问题**；
- **代价**：融合分只反映"排第几"，**不含相关性含义**；本项目权重和为 1，所以**上限只有 1/61 ≈ 0.0164**；
- 因此绝对阈值（0.65）在融合分上**没有判定力**：要么全滤掉，要么无意义；
- 更关键：**在融合前用绝对阈值过滤，会破坏多路互补**（稀疏路能救回来的片段被提前杀掉）；
- 正确做法：阈值只用于**单路绝对分**；融合后取 top-k，需要绝对判定就上 **rerank**。

---

### T4. 切片参数 600/100 怎么定的？如果改成 200/20 会怎样？

**考察点**：是否理解 chunk 的**权衡**，而不是抄参数。

**答题要点**：
- 切太大：噪声多、语义被稀释、浪费上下文 token；
- 切太小：语义被切断、上下文缺失 → 召回回来的片段"看着相关但答不了问题"；
- **overlap 的作用**是防止句子跨块时语义被截断（本项目约 1/6）；
- 200/20 的后果：切片数暴涨（库更大、检索更慢），单块信息量不足，**生成阶段要拼更多块**，还可能拼出前后矛盾的片段；
- 加分：**参数应该用评测集调**（对比不同 chunk 下的召回率与答案质量），不是拍脑袋。

---

### T5. NL2Cypher 生成的语句，你怎么保证它不会删库、或者拖垮数据库？

**考察点**：LLM 输出的**安全治理**，这是简历里最硬的一条。

**答题要点**：
四层防护：
1. **参数化**：实体一律 `$entity`，绝不字符串拼接 → 防注入；
2. **规则校验**（先跑，零成本）：拒绝写关键字（CREATE/MERGE/DELETE/SET/DROP/CALL…）+ 必须读语句开头（MATCH/OPTIONAL MATCH/WITH/UNWIND/RETURN）+ label/关系名走 **schema 白名单** + **强制补 LIMIT**；
3. **EXPLAIN 预检**：让 Neo4j 只生成执行计划、**不执行原查询**，验证语法与语义；
4. **只读会话**：连接层 `default_access_mode="READ"` 兜底；
- 另外：**生成的语句只进日志，不进用户响应**（不暴露内部实现）。

---

### T6. 图谱通路的三级递进为什么这么排？顺序能换吗？

**考察点**：能否说清"**成本-确定性-可用性**"的排序逻辑。

**答题要点**：
```
① 模板精确查询（QAType 元数据，零 LLM、毫秒级、结果确定）
   ↓ 查空
② NL2Cypher（LLM 生成 Cypher，覆盖模板外的关系，有成本与失败率）
   ↓ 仍空
③ 规则兜底链（词典 + 规则拼 Cypher，零 LLM）
```
- **顺序不能换**：先用最便宜最确定的，命中了就不必花钱；LLM 放在第二位是因为它能覆盖模板覆盖不到的关系；
- ③ 的价值是**可用性兜底**：大模型不可用时，图谱能力不中断（这是"降级不阻断"的关键一环）；
- 加分：能指出"③ 的结果质量低于 ②，所以只在前两层都拿不到时才用"。

---

### T7. ReAct 的"多跳"具体怎么实现的？步数怎么控制？失败了怎么办？

**考察点**：是否真的理解 ReAct 的运行机制。

**答题要点**：
- **循环**：`思考 → 行动（调工具）→ 观察 → 再思考`，由 LLM 决定下一步；
- **多跳的关键是状态累积**：LangGraph 用 `add_messages` reducer **追加**消息（用户问题 + 历次 AI 决策 + 每次工具返回），所以下一轮能看到**完整历史**，才能"先查药、再据药名查厂家"；
- **步数控制**：`RECURSION_LIMIT`（本项目 10），防无限循环与成本失控；
- **失败处理**：工具**返回可读字符串而非抛异常** → 失败被降级为"观察结果"，LLM 可自主转向或诚实说查不到；
- **兜底**：ReAct 整体失败（超步数/异常/空回答）→ 回落 `HybridAgent` 的自动路由，保证不空手而归。

---

### T8. 为什么事实护栏要独立成第二次 LLM 调用？为什么温度是 0？

**考察点**：防幻觉方案的**设计动机**。

**答题要点**：
- **自检偏见**：同一轮里既生成又自查，模型倾向**给自己刚写的答案辩护**；生成目标（说完整、说顺）与核查目标（挑刺、逐条对证据）**方向相反**；
- 第二次调用时，模型面对的是"**一段声明 + 一段证据**"的干净任务，没有"维护自己答案"的包袱；
- **温度 0**：核查要的是**稳定判定**（同一输入给同一结论），不是多样性；
- 另外两点：**输出格式不同**（生成是自然语言、核查是结构化 JSON）、**职责分离可复用**（多个 Agent 共用同一个护栏）；
- **fail-open**：护栏异常/无上下文时放行，绝不因为"检查失败"中断问答。

---

### T9. 你说 147 个测试用例"全离线"，怎么做到的？架构上做了什么保证？

**考察点**：是否真的理解**依赖倒置的收益**。

**答题要点**：
- **端口-适配器**：domain 定义 `Protocol`（LLM / GraphStore / LiteratureSearch / CacheStore / EntityRecognizer），infrastructure 反向实现 → 领域层**不 import 任何 SDK**；
- 测试用**替身注入**（`tests/conftest.py` 的 FakeLLM / FakeGraph / FakeRecognizer / FakeLiterature），所以**不连 Neo4j / Milvus / LLM、不需要 Docker**；
- **架构约束由测试固化**：`test_architecture.py` 用 AST 静态检查依赖方向（domain 不得 import 外层、application 只有组合根可碰 infrastructure、interfaces 不得碰数据资源）；
- `test_ports.py` 用 `isinstance`（`@runtime_checkable`）做端口契约的结构检查；
- 收益：CI 里**不需要起任何外部服务**，秒级反馈。

---

### T10. 如果并发到 100 QPS，这套系统哪里最先崩？怎么优化？

**考察点**：**性能与容量思维**（很多人只讲功能不讲这个）。

**答题要点**：
- **最先崩的是 LLM**：每问至少 1 次生成 + 1 次护栏（ReAct 更多），有速率限制、延迟秒级、还有成本 → 一定是瓶颈；
- 优化顺序：
  1. **缓存**：相同问题直接命中（已实现 Redis 缓存 + 幂等锁防击穿）；
  2. **降级开关**：护栏可关闭（省一次调用）、ReAct 超步数回落固定流水线；
  3. **访问控制**：限流、排队、熔断；
  4. **连接层**：Neo4j / Milvus 连接池、只读副本；
  5. **异步化**：FastAPI 用 async 端点 + 外部调用异步化，提升并发吞吐；
  6. **减少不必要的 LLM 调用**：能用模板/规则答的别走 LLM（18 类快路径就是这个思路）；
- 一句话：**"先保证不被打挂（限流+缓存+降级），再谈提升吞吐"**。

# 三、追问链（面试官最常用的深挖路径）

| 起点 | 会被追问到 |
|---|---|
| **混合检索 / RRF** | → 那为什么不直接上 rerank？→ rerank 模型怎么选（cross-encoder vs LLM 打分）？→ 加了 rerank 时延涨多少、值不值？ |
| **事实护栏** | → 护栏会不会误报（把有依据的判成无依据）？→ 误报怎么处理？→ 你怎么评测护栏本身的效果？ |
| **NL2Cypher 安全** | → 如果 LLM 生成了一条语法合法但**极慢**的查询呢？→ 除了 LIMIT 你还怎么防？（超时、查询计划评估）→ EXPLAIN 能发现性能问题吗？ |
| **ReAct Agent** | → 步数上限怎么定？→ 模型陷入循环怎么办？→ 工具调用失败重试吗？→ 怎么控制成本？ |
| **三层递进** | → 模板覆盖了多少比例的问题？→ ①②③ 各自的命中率你怎么测的？→ ③ 的结果质量差，怎么让用户不察觉？ |
| **147 个离线测试** | → 那**真实依赖**怎么测？→ 有没有集成测试/端到端测试？→ 上线前怎么验收？ |
