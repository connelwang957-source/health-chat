## 2. 核心数据流

### 2.1 `hybrid` 模式（默认）

```text
用户问题
   ↓
[1] 双路召回
    ├─ 图谱召回 _graph_recall()：NL2Cypher.answer() → LLM 生成 Cypher
    │                          → 规则 + EXPLAIN 校验 → 执行 → 格式化
    │                          失败则降级为空，不阻塞
    └─ 向量召回 RAGAgent.recall()：Milvus 检索 → 拼接带「来源 + 页码」的上下文
   ↓
[2] 融合生成：DeepSeek 结合 <graph_facts> 与 <context> 两路信息生成中文回答
   ↓
[3] 事实护栏 _guard()：第二次 LLM 调用核查答案是否有据可依
                        无依据 → 在答案末尾追加「请谨慎参考」提醒
   ↓
输出
```

### 2.2 `agent` 模式

不是固定流水线，而是 ReAct 循环（LangGraph `create_react_agent`）：

```text
用户问题 → [LLM 自主决策] → 调 search_documents / query_knowledge_graph
        → 观察工具结果 → 继续决策 → … → 给出回答
   ↓
[2] 从 messages 历史中过滤 ToolMessage，拼接作为护栏依据（未调工具则上下文为空、自动跳过）
   ↓
[3] 事实护栏
```

`agent` 模式补齐了 `hybrid` 的两块短板：简单问题不再强制双路召回；
多跳问题（先查图谱、再据结果决定查哪篇文献）由 LLM 自主编排。

## 3. 自动选路（FR-024）与备用处理（FR-026）

`HybridAgent._route` 的优先级：

```text
开放式问题（进展 / 因果 / 对比）→ 有实体：hybrid 双路 ｜ 无实体：rag 文献
可枚举的信息需求（命中固定类型或有实体）→ kg 结构化知识
寒暄 / 常识（无实体、无类型、非开放式）→ direct 不检索
```

**开放程度优先于"命中了哪一类"**：像"2型糖尿病的药物治疗有哪些新进展"，
虽然沾了"药物治疗"的边（关键词表会命中），但它问的是研究进展，模板答不了，
必须去查文献——否则会出现"有相关文献却回一句资料未收录"。

`open_ended` 由两处共同判定：LLM 的 `open_ended` 字段，以及
`domain/rules/openness.py` 的开放信号词（收窄到真正指向"研究 / 因果 / 比较"的词）。

**FR-026**：`needs_retry()` 只在**依据不足（reliability = low）**时换通路（最多 2 次，`direct` 不参与）。

## 4. 事实护栏（`domain/guardrail/fact_guardrail.py`）

生成之后**用 LLM 做第二次调用**，核查答案中的关键医学陈述是否都能在参考上下文中找到依据。

```python
class FactGuardrail:
    def __init__(self, llm: LLM): ...
    def check(self, answer: str, context: str) -> dict:
        # → {"grounded": bool, "unsupported": [...], "reason": str, "raw": str}
```

| 设计点 | 口径 |
|---|---|
| **为什么要第二次调用** | 避免**自检偏见**：同一轮里既当答题者又当裁判时，模型倾向为已写出的答案辩护。分开调用后，它面对的是"一段声明 + 一段证据"的干净任务 |
| **降级放行（fail-open）** | 无上下文、JSON 解析失败、LLM 异常 → 一律 `grounded=True`，**绝不阻塞问答** |
| **提醒不拦截** | 无依据时用 `add_unsupported_note()` 在答案末尾追加「（提醒：以上回答中部分内容（xxx）在当前知识库中未找到直接依据，请谨慎参考。）」——医疗场景下的责任边界选择 |
| **可关闭** | `HybridAgent(enable_guardrail=False)` / `GUARDRAIL_ENABLED=false` |

## 5. 图谱通路：主路径 + 兜底

`NL2CypherAgent` 按顺序取证据，前一层拿不到才走下一层：

```text
① 模板精确查询（QAType 元数据）      零 LLM、结果确定
   └─ 查空 ─▶ ② NL2Cypher（LLM 生成 Cypher + 规则/EXPLAIN 双校验）
                └─ 仍空 ─▶ ③ 规则兜底链（fallback/：词典 + 规则拼 Cypher，零 LLM）
```

第 ③ 层是"大模型挂了，图谱能力不挂"的保证：它完全不调用 LLM。

**安全约束**：Cypher 一律参数化（`$entity`）、走只读会话；`validators.py` 先做写操作关键字检查，
再用 `EXPLAIN` 做服务端预检；LLM 生成的语句**只进日志**，不进入用户可见响应。

## 6. 依据分级（FR-023）

| 情形 | 级别 |
|---|---|
| 仅有结构化知识（KG 命中、无文献） | `high` |
| 含文献（多来源综合或仅文献） | `partial` |
| 无检索依据 / `direct` | `low` |

## 7. 缓存（`--cache`，可选）

`cli.py` 按文档用法取模块级实例：`from xinglin.infrastructure.cache import redis_manager`，
再用 `redis_manager.get_or_compute(key, lambda: bot.chat_main(q).model_dump(mode="json"))` 包裹问答。

`infrastructure/cache.py` 覆盖缓存三件套：**穿透**（负缓存）、**击穿**（SETNX 幂等锁）、
**雪崩**（TTL）。Redis 不可用时 `available=False`，问答照常（只是没了秒回）。

排查异常时注意：**缓存里可能留着改代码之前的结果**，清一次即可——

```bat
docker exec xinglin-redis redis-cli FLUSHDB
```

## 10. 前端

`frontend/index.html` 是**单文件对话界面**（零依赖、零构建），由 `interfaces/web.py`
托管在 `/`，展示最终 Agent 的问答结果。

| 区域 | 内容 |
|---|---|
| 顶栏 | 品牌 + **依赖状态胶囊**（30 秒轮询 `/health`，异常时直接列出挂掉的依赖）+ **深浅色切换按钮** |
| 输入区 | 多行输入、字数计数（上限 500）、示例问题 chips、提问按钮（带加载态） |
| 结果卡片 | 状态提示条（依据不足 / 服务不可用 / 被拒绝）、可靠性 + 检索模式标签、回答正文、健康风险提示、**来源依据**（可折叠：知识图谱 / 医学文献 分别成条）、复制回答 |
| 底部 | 固定免责声明 |

**深浅色主题**：

- 用 CSS 变量 + `html[data-theme="light"]` 覆盖一套取值，配色整体反转（深蓝黑 ↔ 浅灰白）；
- 顶栏按钮一点即在 `dark` / `light` 间切换，选择写入 `localStorage` 持久化；
- `<head>` 里有一段内联脚本**在首屏渲染前**应用主题，避免刷新时闪白/闪黑；
- 首次访问跟随系统偏好（`prefers-color-scheme`）。

**接口**：`POST /v1/chat`（问答）、`GET /health`（探活）。
页面也可直接双击打开——此时 `API_BASE` 自动指向 `http://127.0.0.1:8000`。
