# 项目结构与文件说明

说明每个目录、每个 Python 文件的职责，以及运行期用到的数据资源。
结构对照《项目开发指导》§7.2 的目录树。

```text
xinglin_plus/
├── main.py                     统一入口（根目录运行）
├── readme.md                   快速上手
├── requirements.txt            依赖清单
├── run_cli.bat / run_web.bat   一键启动
├── .env                        环境配置（密钥只读系统环境变量）
├── frontend/                   对话界面（单文件，深/浅色主题）
├── xinglin/                    ★ 主包（四层 + fallback 兜底）
├── tests/                      单元测试（全离线，206 个用例）
├── evals/                      效果评测与消融（真机跑，产物为报告）
├── data/                       数据源：medical.json + pdfs/
├── dict/                       8 类医学词典
├── docs/                       本文档所在
└── models/                     本地模型目录（当前为空）
```

---

## 一、`xinglin/` 主包

### 顶层

| 文件 | 作用 |
|---|---|
| `config.py` | 全局配置：Neo4j / LLM / Milvus / Redis / 数据路径 / 切片 / 阈值。**不 import 任何业务模块**，是全项目最底层依赖 |

### `interfaces/`（接口层：对外入口）

| 文件 | 作用 |
|---|---|
| `cli.py` | 命令行：解析 `--mode` / `--cache`，驱动交互循环；`--cache` 时经**应用层**取用缓存（接口层不直接碰基础设施） |
| `web.py` | FastAPI：`POST /v1/chat` 问答、`GET /health` 探活、`GET /` 托管前端；`python -m` 启动，模式只在启动时指定 |

### `frontend/`（对外页面，位于项目根目录）

| 文件 | 作用 |
|---|---|
| `index.html` | **单文件对话界面**（零依赖、零构建）：顶栏（品牌 + 依赖状态胶囊 + **深浅色切换**）、输入区（字数计数 / 示例问题）、结果卡片（可靠性 / 模式标签、回答正文、风险提示、来源依据可折叠、复制回答）、底部免责声明。由 `interfaces/web.py` 托管在 `/`，也可直接双击打开 |

### `application/`（应用编排层：用例）

| 文件 | 作用 |
|---|---|
| `runtime.py` | **组合根**：把基础设施适配器注入领域服务（`@lru_cache` 保证重对象只建一次）；也是 application 里唯一允许 import infrastructure 的文件 |
| `hybrid_agent.py` | `HybridAgent`：**默认形态**。双路召回 + FR-024 自动选路 + FR-026 换路重试 + 事实护栏 |
| `rag_agent.py` | `RAGAgent`：仅文献。`recall()` 返回带「来源文件 + 页码」的上下文文本；`collect_docs()` 给 ReAct 工具用 |
| `nl2cypher_agent.py` | `NL2CypherAgent`：仅图谱。主路径 NL2Cypher，失败回落第 1 代规则链 |
| `tool_agent.py` | `ToolCallingAgent`：ReAct 循环（`create_react_agent`），LLM 自主决定调哪个工具、调几次；证据经收集器回填，收尾同样过**事实护栏**，循环异常回落自动问答链路 |
| `tools.py` | `build_tools()`：把「图谱查询 / 文献检索」包装成两个 LangChain `@tool` |

### `domain/`（领域层：业务能力，只依赖端口）

| 文件 | 作用 |
|---|---|
| `ports.py` | 端口（`Protocol`）：`LLM` / `GraphStore` / `LiteratureSearch` / `CacheStore` / `EntityRecognizer` |
| `entities.py` | 领域实体：`Question` / `Intent` / `Fact` / `Source` / `Answer` |
| `values.py` | 值对象：`EntityRole` / `Mode` / `Reliability` / `SourceType` / **`QAType`（固定问答类型：第 9 章 18 类 + 科室 2 类）** |
| `graph/nl2cypher.py` | NL2Cypher 能力：生成 → 校验 → 执行 → 格式化 |
| `graph/schemas.py` | 图谱 schema（7 类节点 / 10 类关系）与提示词渲染 |
| `graph/prompts.py` | NL2Cypher 的 system / user 提示词 |
| `graph/validators.py` | Cypher 校验：只读关键字规则 + `EXPLAIN` 预检 |
| `graph/build_graph.py` | 一次性建图脚本（`python -m xinglin.domain.graph.build_graph`） |
| `rag/embeddings.py` | 向量模型工厂（自有 HuggingFace，本地加载） |
| `rag/vectorstore.py` | 向量库能力：切片 / 建库 / 检索 / 混合检索（稠密 + 稀疏 → RRF） |
| `guardrail/fact_guardrail.py` | **事实护栏**：`FactGuardrail(llm)` 用 LLM 二次核查答案是否被上下文支撑；`build_context`（拼证据）与 `guard_answer`（核查+追提醒）是**各对话链路共用的单一出口** |
| `rules/` | 第 10 章业务规则（纯函数）：宜忌判定 / 默认意图 / 信息不足 / 风险提示 / 非法拦截 / 关键词表 / 开放式判定 / 话术模板 |
| `services/` | 领域服务：意图分类、图谱查询、文献检索、生成、依据分级、缓存 |

### `infrastructure/`（基础设施层：端口实现）

| 文件 | 作用 |
|---|---|
| `llm.py` | `create_llm()`（LangChain ChatOpenAI）+ `OpenAILlm`（实现 `LLM` 端口） |
| `graph.py` | `Neo4jGraph`：实现 `GraphStore`，只读会话 + 参数化 Cypher |
| `cache.py` | `RedisManager` + 模块级 `redis_manager`：JSON 读写、SETNX 幂等锁、`get_or_compute` |
| `init_data/export_dict.py` | 从图谱导出 8 类词典（`dict/*.txt`） |

### `fallback/`（第 1 代规则流水线：零 LLM 兜底）

| 文件 | 作用 |
|---|---|
| `dictionary.py` | `MedicalDictionary`：8 类词典 + **最长优先**实体识别（实现 `EntityRecognizer`） |
| `question_classifier_v2.py` | 规则判定 `QAType`（实体角色优先 → 关键词表 → 默认规则） |
| `question_parser_v2.py` | `sql_transfer()`：规则拼参数化 Cypher（复用 domain 模板） |
| `answer_search_v2.py` | 执行查询 + 模板化组织回答（复用 domain 话术） |
| `robot_qwen.py` | `xing_lin()` 工厂 + `RobotQwen`：编排以上四步，可选 Qwen 兜底 |

## 二、数据 / 资源

| 数据 | 位置 | 形态 | 谁在用 |
|---|---|---|---|
| 医疗原始数据 | `data/medical.json` | 8808 条疾病记录 | 建图脚本输入（非运行期依赖） |
| 医学文献 PDF | `data/pdfs/` | 20 篇 | 重建向量索引时才用 |
| 医学词典 | `dict/*.txt` | 8 个文件 | 实体识别（意图分类 + 规则兜底链） |
| 稀疏检索语料 | `data/bm25_docs.json` | 切片正文 + 元数据 | 稀疏路 BM25 |
| 知识图谱 | Neo4j | 库 `medical`，7 类节点 / 10 类关系 | 结构化知识 |
| 文献向量 | Milvus | 集合 `medical_lit`，762 条 × 384 维 | 稠密检索 |

> 按文档 §2.5：这些**不是代码模块**（不能被 import），而是「数据 / 资源层」，
> 由 `domain/rag`、`domain/graph` 读写；interfaces 层不得直接碰。

### 常用数据脚本（仅在需要时运行）

```bat
REM 稀疏路语料：从既有向量集合导出（换机器 / 清了 data 目录后）
.venv\Scripts\python.exe -X utf8 -m xinglin.domain.rag.vectorstore --export-bm25

REM 词典：从图谱重新导出
.venv\Scripts\python.exe -X utf8 -m xinglin.infrastructure.init_data.export_dict

REM 建图（可选）：MERGE 幂等，建议先干跑看统计
.venv\Scripts\python.exe -X utf8 -m xinglin.domain.graph.build_graph --limit 300
.venv\Scripts\python.exe -X utf8 -m xinglin.domain.graph.build_graph --write
```

## 四、`evals/`（效果评测与消融，真机跑）

与 `tests/` 分工明确：`tests/` 管"**逻辑对不对**"，`evals/` 管"**效果好不好**"——
后者需要真实的图谱 / 向量库 / 模型服务，因此不放进 CI，产物是报告。

| 文件 | 作用 |
|---|---|
| `run_eval.py` | 分层效果评测（固定问答 / 开放式 / 边界 / 安全）→ 通过率、工具命中率、时延、护栏触发 |
| `degradation.py` | 依赖逐一失效的容错验证（图谱 / 向量库 / 模型 Key / 缓存 / 护栏超时 / 护栏返回乱码） |
| `ablation.py` | 检索消融、**融合权重扫参**、护栏混淆矩阵、图谱消融 |
| `performance.py` | 时延构成、并发阶梯、两种编排方式的时延对比 |
| `dataset/build_fixed_qa.py` | 从图谱**自动生成**固定问答评测集（真值查询手写，不复用生产实现） |
| `dataset/build_open_ended.py` | 从文献主题反推开放式题目（含必含要点、通用禁区、语料覆盖自检） |
| `dataset/build_semantic.py` | 语义改写题集（问法刻意避开标题词组，用于公平评价检索两路） |
| `dataset/*.jsonl` | 评测集成品：固定问答 160 / 开放式 57 / 语义改写 19 / 边界 16 / 安全 12 |
| `reports/` | 历次评测报告（markdown，可对比演进） |

**一句话提醒**：`evals/` 的真值必须独立于被测实现——否则实现错了，真值会跟着错，评测永远"通过"。
